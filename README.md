# Horizon Privacy Patcher

Экспериментальный патчер для **Windows x64**, неофициальный и не связанный с Horizon, Mojang или Microsoft. Он не изменяет игровой клиент и использует только официальные сборки игры. Источники Minecraft должны быть получены пользователем законно.

## Что делает

- GitHub Actions берёт официальный релиз Horizon, проверяет подпись и контрольные суммы официальных архивов, применяет `patches/privacy.patch` к исходникам и собирает лаунчер и один портативный `HorizonPatcher.exe`.
- Патчер ищет `horizon-launcher.exe` в распространённых папках (не более трёх секунд) или предлагает выбрать EXE вручную. Он поддерживает и EXE, извлечённый из портативного ZIP; установщики и другие форматы не модифицирует.
- Перед заменой проверяется SHA-256: разрешён только официальный EXE той версии, под которую собрана текущая сборка патчера, или ранее установленный им EXE, чья контрольная сумма сохранена локально. Неизвестный файл отклоняется. Закройте лаунчер до патчинга.
- Патчер заменяет EXE средствами Windows без постоянной резервной копии. Файлы игры и миры он не удаляет. Для восстановления официальной версии скачайте её у разработчика.
- Изменённый лаунчер разрешает офлайн-игру с существующими файлами Minecraft, включает штатный `HORIZON_TELEMETRY_URL=off` для себя и запускаемых дочерних процессов и обнаруживает папку ElyPrism в `%APPDATA%\ElyPrismLauncher`. Это обнаружение файлов/экземпляров, не поддержка авторизации Ely.by.
- По умолчанию данные лаунчера и его хранилище ключей отделены от официального лаунчера. Миры могут использовать штатное расположение Horizon; резервные копии миров всё равно необходимы.

## Обновления

Патчер проверяет последнюю публичную версию GitHub Release **только при открытии патчера**. Если доступна новая версия, он скачивает EXE из GitHub, проверяет SHA-256 по метаданным релиза, заменяет собственный файл и запускает новую версию. Если GitHub недоступен, появляется предупреждение и открывается имеющаяся версия. Если установить найденное обновление не удалось, появится ошибка; для замены нужны права записи в папку патчера.

Фоновые проверки и задачи по расписанию больше не создаются. При запуске новая версия удаляет собственные задачи старых версий, не затрагивая задачи с изменёнными действиями. Для перехода на этот режим необходимо один раз вручную скачать новую версию патчера и заменить старый EXE. Прежняя фоновая задача при следующей проверке может скачать эту версию и удалить себя, но старый EXE патчера останется прежним и при его использовании может снова создать задачу. Новая версия патчера не меняет лаунчер без выбора пользователя; применять патч нужно в окне программы.

Встроенное самообновление модифицированного лаунчера отключено, чтобы оно не заменило изменения официальным EXE. Workflow проверяет релизы upstream примерно каждые 30 минут (GitHub может задерживать расписание). Если обычное применение патча не удалось, он пробует трёхстороннее объединение с закреплённой базовой версией. Обновление выпускается **только если** объединение прошло без конфликтов и тесты/сборка прошли. При конфликте или сбое проверок нужна ручная доработка; тесты не дают гарантии совместимости с любой будущей версией. Невозможно гарантировать работу с любым будущим бинарником или форматами; внешняя программа всё равно может заменить файл между проверками. Не запускайте неподтверждённую версию, если для вас критичны настройки приватности.

### Быстрый релиз после PR

После объединения PR из этого же репозитория workflow может использовать лаунчер, уже собранный и проверенный в успешной сборке PR. Сверяются итоговое дерево файлов, версия и commit исходного Horizon, хеш официального EXE, параметры компиляции и SHA-256 артефакта. Артефакты форков не используются; при отсутствии артефакта или несовпадении данных выполняется обычная полная сборка. Проверка подписи upstream, тесты патчера и проверка установки по-прежнему выполняются на main. Время зависит от GitHub и не гарантируется.

## Ограничения безопасности

Отключение штатной телеметрии не означает отсутствие других сетевых запросов: загрузки, GitHub, Mojang и игровые серверы могут использовать сеть. Проверки не доказывают отсутствие всех ошибок и не заменяют независимый аудит. Выпускаемый EXE не имеет собственной цифровой подписи. Патчер доверяет TLS и этому GitHub-репозиторию; его владелец и CI могут выпустить новый исполняемый файл, который обновление загрузит автоматически. Не вводите данные Microsoft в этот патчер.

Microsoft-вход не обязателен. Для его работы в собственной сборке необходимо настроить в GitHub Actions переменную `HORIZON_MSA_CLIENT_ID` с разрешённым Microsoft application client ID. Без неё вход Microsoft не настроен, но офлайн-режим может использовать уже имеющиеся локальные файлы Minecraft. Серверы с обязательной онлайн-аутентификацией без входа не работают. Java-экземпляры и Java-моды не становятся автоматически совместимыми с Horizon.

Окно патчера показывает совместимую версию Horizon и открывает в браузере ссылку на её официальный установщик Windows x64. Он не патчится и не запускается автоматически: после установки выберите `horizon-launcher.exe` в патчере.

## Установка

1. Скачайте `HorizonPatcher.exe` из GitHub Releases после успешной сборки.
2. Закройте лаунчер, запустите патчер и выберите найденный файл или укажите EXE вручную в окне.
3. При следующем запуске патчер проверит свою версию; фоновых задач обновления он не создаёт.

Окно использует встроенные Windows PowerShell и Windows Forms; интернет для самого интерфейса не нужен.

## Локальная разработка

Нужны Rust, Git, Windows SDK и официальные исходники соответствующего релиза. Workflow является описанием полного процесса. `PATCH_PAYLOAD` — путь к gzip-файлу собранного лаунчера; `PATCH_PAYLOAD_SHA256` — SHA-256 несжатого EXE; `OFFICIAL_SHA256` — хэш официального EXE; `PATCHER_BUILD_TAG` — тег публикуемого релиза. В тестах используются временные фиктивные файлы; реальные лаунчеры и аккаунты не нужны. После первой успешной сборки проверенный лаунчер кэшируется; при неизменных исходниках и настройках повторные сборки быстрее. Для нового upstream или изменённого патча нужна полная сборка.

### Офлайн-запуск Java и Fabric

Для офлайн-профиля выберите нужную версию Minecraft, уже установленную в ElyPrism или другом поддерживаемом лаунчере. Horizon проверяет контрольные суммы и копирует необходимые файлы в собственный кэш, не изменяя исходную установку. Если файлы неполные, запустите эту версию в другом лаунчере и повторите попытку. Кэш занимает дополнительное место. Установка Fabric и метаданные могут требовать интернет; серверы с проверкой лицензии по-прежнему требуют действующий онлайн-аккаунт. Это не авторизация Ely.by.
